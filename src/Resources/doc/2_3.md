### 2.3 Custom initialization

The default include loads the browser library, renders bundle configuration, and
initializes queued forms:

```twig
{{ include('@FpJsFormValidator/javascripts.html.twig') }}
```

Conceptually, it does the following:

```twig
<script src="{{ asset('bundles/fpjsformvalidator/js/fp_js_validator.js') }}" type="text/javascript"></script>
{{ js_validator_config() }}
{{ init_js_validation() }}
```

The original project generated `fp_js_validator.js` with Assetic. On modern
Symfony applications, provide the combined asset from your own build step, or
load the files listed in the README in the documented order.

If you want to customize initialization, load the library and config in the
layout:

```twig
<head>
    <script src="{{ asset('bundles/fpjsformvalidator/js/fp_js_validator.js') }}" type="text/javascript"></script>
    {{ js_validator_config() }}
</head>
```

Then render form models where you need them:

```twig
{{ form(comment) }}
{{ init_js_validation(comment) }}

{{ form(user) }}
{{ init_js_validation(user) }}
```

`init_js_validation()` accepts three arguments:

```text
init_js_validation(form = null, onLoad = true, wrapped = true)
```

- `form`: By default, all queued forms are processed. Pass a form name or
  `FormView` instance to process only one form.
- `onLoad`: When `true`, validation models are initialized on document ready.
  Pass `false` when you want to initialize them yourself.
- `wrapped`: When `true`, the generated code is wrapped in a
  `<script type="text/javascript">...</script>` tag.

For example, to initialize validation after an Ajax request:

```twig
{{ form(user) }}

<script type="text/javascript">
    $.ajax({
        // ...
        complete: function() {
            {{ init_js_validation(null, false, false) }}
        }
    });
</script>
```

In that call:

- `null` means all queued forms will be rendered.
- The first `false` disables document-ready initialization.
- The second `false` prevents an extra `<script>` wrapper.
